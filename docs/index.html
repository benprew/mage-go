What Is This?

mage-go is a ground-up Magic: The Gathering rules engine, written in Go and inspired by XMage's fifteen years of open-source rules enforcement. It is not a port—it is a reimplementation using idiomatic Go: flat interfaces, composition over inheritance, and functional options instead of deep class hierarchies.

Two-player only. The card pool covers early Magic—from Alpha through roughly the Odyssey/Onslaught block era. No planeswalkers. No energy. No sagas. Just the raw, beautiful complexity of old-school Magic.

Architecture

Effects

The core abstraction. One-shot effects resolve from the stack. Continuous effects recompute every cycle in MTG layer order.

Triggers

Event-driven triggered abilities with condition predicates. New triggers need no engine changes.

Attrs

Keywords, capabilities, and type identity unified as additive integer counts. Grant and revoke compose naturally.

Mutations

Effects never touch *Game directly. GameMutator keeps the set of legal mutations explicit and auditable.

The Stack

Standard LIFO queue unifying spells and abilities. Priority passing, SBAs between resolutions. By the book.

Combat

Banding, first strike, double strike, trample, protection, damage prevention, redirection, and reflection.

Play

A terminal UI lets you play against an AI opponent locally. An SSH server supports human-vs-human games over the network. Both are rough prototypes—functional, not polished.

Test-Driven, Card by Card

Every card begins as a failing test. The test harness DSL makes it natural to script game scenarios:

func TestLightningBolt(t *testing.T) {
    g := gametest.NewTestGame(t)
    g.AddCard(ZoneHand, gametest.PlayerA, "Lightning Bolt")
    g.CastSpell(1, Precombat, gametest.PlayerA,
        "Lightning Bolt", gametest.PlayerB)
    g.StopAt(1, EndStep)
    g.Execute()
    g.AssertLife(gametest.PlayerB, 17)
}
